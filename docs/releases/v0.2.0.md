# v0.2.0 release candidate: real Collector processor chains

`otel-policy-lab` can execute representative OTLP fixtures through processor chains running inside your selected OpenTelemetry Collector binary, capture the real output locally, and evaluate it against telemetry governance policies.

Select `--runner otelcol --otelcol-bin <preinstalled-binary>`. Original processor definitions/order are retained, while production receivers and exporters are replaced with local OTLP components. The CLI and action do not download binaries and never fall back to simulation.

## Added

- Full-fidelity OTLP transmission and local three-signal capture.
- Strict topology validation: one pipeline per signal; no connectors, routing, provider expansion or ambiguous YAML.
- Bounded startup/run/shutdown lifecycle, cancellation, Unix process-group cleanup and private temporary configuration.
- Schema 2 execution reports with version/binary/harness provenance, counts, deadlines, timings and process status.
- PASS/FAIL/INCONCLUSIVE/ERROR semantics, including conservative applicability checks and safe execution errors.
- GitHub Action runner/binary/timing inputs and `report-path` output.
- Checksum-pinned real-Collector integration CI, lifecycle/security tests, and a real three-signal example.

## Compatibility

The default stays `fixture`; fixture schema 1, golden output formatting and exit-code conventions are retained. The explicit `--otelcol-bin` requirement applies to real execution. Standalone validation retains its existing default binary lookup.

One v0.2 correctness change applies to both runners: maximum series per metric now counts the union across resource blocks and export requests, rather than checking each metric record separately. Structurally encoded series identities also prevent delimiter-containing values from collapsing distinct series. Configurations previously passing because of that undercount can now fail correctly.

Real runs return exit 4 for inconclusive evidence and 3 for runner errors. `tail_sampling` and `groupbytrace` absence-based assertions remain conservative because elapsed settling alone cannot establish completion. Proven captured violations still fail, and capture of all requested error-span identities still establishes preservation.

## Boundaries

This tests fixture-local processor behaviour, not a production deployment. Trusted supplied code inherits the environment and can have side effects; replacing exporters is not an OS network sandbox. Real lifecycle support is macOS/Linux. Custom distributions must support the generated OTLP harness and standard Collector readiness logging. Reports omit raw diagnostics/configuration/telemetry.

See [usage and limits](../real-collector-runner.md), [schema 2](../report-v2.schema.json) and [test evidence](../TESTPLAN.md). GitHub-hosted action smoke and Linux performance checks are configured for CI; the local verification is not a substitute for a CI run before tagging a release.
